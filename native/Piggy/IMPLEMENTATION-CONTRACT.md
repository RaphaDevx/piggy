# Native implementation contract

All iOS UI and client logic Swift/SwiftUI. Existing Expo app retained. Root source native/Piggy/Sources, resources native/Piggy/Resources. Root owns App entry, Theme, Onboarding, Mascot, Monetization, assets/project generator and docs. Services agent owns Sources/Core and Sources/Services AND only new supabase/functions/native-finance/index.ts. Screens agent owns Sources/Screens only. No overlapping writes. Shared cross-agent design changes by message.

Use Supabase Swift SDK 2.x via SPM, RevenueCat 5.x and GoogleMobileAds 12.x SPM as appropriate. iOS17 minimum for new SwiftUI app. Same existing bundle com.heartbeat.piggy; no product creation/release. Do not claim Apple SDK compilation on Linux.

Model/interface contract (services agent may add fields but coordinate renames):
- @MainActor final class PiggyStore: ObservableObject, init(), @Published userID: UUID?, receipts:[Receipt], friends:[Friend], requests:[Friend], projects:[Project], profile:Profile?, busy:Bool, errorMessage:String?; configured:Bool; aiConsent:Bool get/set; start() async; reload() async; signInGoogle() async throws; signInApple(idToken:String, nonce:String) async throws; signOut() async; deleteAccount(authorizationCode:String?) async throws.
- Receipt: Identifiable Codable Hashable with id UUID, user_id UUID, store_name String, receipt_date String?, total_amount Decimal?, currency String, payment_method String?, payment_card String?, image_url String?, notes String?, created_at String, project_id UUID?, receipt_items [ReceiptItem]. ReceiptItem: Identifiable Codable Hashable id UUID, name String, quantity Decimal?, unit_price Decimal?, total_price Decimal?, tags[String], subcategory String?. Use snake_case properties exactly matching API to avoid decoder ambiguity.
- ReceiptDraft: store_name String, receipt_date String, total_amount Decimal, currency String, payment_method String, notes String, raw_ocr_text String, items:[DraftItem]; DraftItem: Identifiable, name String, quantity Decimal, unit_price Decimal, total_price Decimal, tags[String], subcategory String?. Editable bindings.
- Profile: id UUID, display_name String?, piggy_code String. Friend: id UUID friendship ID, profile Profile, status String; Project: id UUID, name String, emoji String, description String?, currency String.
- store.processImage(image:UIImage, allowAI:Bool) async throws -> ReceiptDraft uses Apple Vision locally and scan-receipt only after explicit consent. Save via existing atomic RPC save_separate_receipt_scan with duplicate review decision flow (must not silently dedupe/merge). Methods store.duplicateCandidates(for:ReceiptDraft) -> [Receipt]; save(draft:ReceiptDraft,image:UIImage?,separateFrom:[UUID]) async throws -> UUID; merge(draft:ReceiptDraft,image:UIImage?,target:Receipt) async throws -> UUID; update(receipt:Receipt) async throws; delete(receipt:Receipt) async throws; signedImageURL(path:String) async throws -> URL.
- Social: sendFriendRequest(code:String), respondToFriend(id:UUID,accept:Bool), removeFriend(id:UUID); createProject(name:String,description:String,friendIDs:[UUID]) async throws; assign(receiptID:UUID,projectID:UUID?) async throws; split(receipt:Receipt, participantIDs:[UUID], exclusions:[UUID:Set<UUID>]) async throws. Display splits/balances if existing endpoints allow; never promise successful persistence before all writes confirm.
- Finance: do not duplicate canonical finance-core totals on the Swift client. New authenticated Edge adapter native-finance may call existing finance-core for a native summary response (services agent designs Codable type and coordinates). Receipt-only mode same enabled scope as current app; disabled bank-import feature not silently activated. Money uses Decimal/integer cents; do not add different currencies.
- Root UI: Theme enum provides static background, surface, accent, pink, text, secondary Color. MascotView(pose:String, size:CGFloat=200) uses brand assets/animations, safe static and reduced motion. BrandHeader() shows native logo/Gold badge via GoldManager environmentObject. OnboardingView(onComplete:()->Void) has Skip/Next/Done and accessible paging; App decides persisted completion with @AppStorage. Screens agent may use Theme and MascotView APIs.
- Screens agent entry MainTabs() uses environmentObject PiggyStore + GoldManager. Scanner UI captures using VNDocumentCameraViewController/PhotosPicker -> DraftReview; Dashboard, ReceiptList/Detail/edit, categories/finance, friends/projects/split, profile and settings implement actual backend operations. Root provides GoldView() and GoldManager @Published isGold Bool, available Bool; no technical IDs shown in product UI.
- LoginView can be screens agent or root (coordinate). Root currently owns LoginView. Profile should call store.signOut, delete with confirmation, allow walkthrough replay via NotificationCenter .init("piggy.showOnboarding"), show GoldView sheet and variant selection using @AppStorage("piggy.variant") String default "automatic". Variants render assets, not automatic home-screen icon changes.
- All async failures visible with retry; no fake sample records except explicit preview/demo mode isolated from real data. No TODO placeholder buttons. Keyboard, Dynamic Type and VoiceOver supported. No commit/push/native builds except K-Dev API. Report real verification and remaining gaps.
